# Quantization kernel results

Measured 2026-08-20 on an Apple M5 Max MacBook Pro (18 cores, 128 GB), macOS 26.5.1, arm64, with Rust/Cargo 1.97.1. Criterion intervals below are 95% confidence intervals from release builds (`thin` LTO, one codegen unit, debug symbols). Fixed-seed statistical rows use 1,000 vectors.

## Correctness and model

All values of ρ are normalized RMSE.

| d | sign / b=1 | grid b=2 | grid b=4 |
|---:|---:|---:|---:|
| 128 | 0.599402 | 0.339744 | 0.097083 |
| 768 | 0.602181 | 0.341993 | 0.097314 |
| 1536 | 0.602492 | 0.342547 | 0.097498 |

The independent d=1536 sign convention anchor is within 0.01 of `sqrt(1 - 2/pi) = 0.6028`. The exhaustive binary16 oracle covers all 65,536 bit patterns. Rotation norm, dot, round-trip, mixing, raw-ChaCha sampler, and seed-42 snapshot tests pass.

|---|---:|

## Assembly audit and SIMD decision

- `sign_plane::score_sym`: tight `eor` loop with ARM NEON `cnt.8b` + `addv.8b`; no intrinsic escalation needed.
- `sign_plane::score_asym`: ARM NEON `cnt.8b` + `addv.8b` per query plane with shift-add accumulation; no intrinsic escalation needed.
- `grid_plane::score`: scalar code extraction, LUT load, and `fadd`, which is acceptable for v1.
- FHT butterfly: scalar `fadd`/`fsub`; a feature-detected NEON experiment measured 5.418 µs at d=768 versus the then-scalar 6.473 µs (1.19×), below the mandatory 1.5× retention threshold, so it was deleted. A subsequent safe slice-loop cleanup is the final scalar implementation and measures 3.789 µs at d=768, faster than that intrinsic experiment.

The final workspace contains no `unsafe` code.
